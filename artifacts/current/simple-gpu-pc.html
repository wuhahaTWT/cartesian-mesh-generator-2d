SIMPLE 为什么慢，GPU 到底加速了什么

Windows PC · RTX 4060 Laptop · 复用现有 CUDA 12.6 / PyTorch · 真实原生方程与输出

结论：1%/5% 单步停止量不能保证解已经接近收敛场；coupled 每轮内部做大量线性工作；GPU Jacobi 在大压力矩阵上有效，但当前 CPU 多重网格更快，小网格完整 CFD 用 GPU 明显更慢。CPU 默认、原生质量门和停止门均保留。

1. 当前软件如何停止

界面默认 1e-6，研究常用 1e-8。strict 要求至少 10 轮，最大归一化动量残差、速度变化和压力变化都小于该容差，局部连续性和全局流量不平衡小于 1e-8，最后还有严格线性求解检查。coupled 另检查面通量一致性。

速度变化是最大单元速度增量除以 Uref；压力变化除以 Uref² + ν·Uref/H；动量残差按动量对角系数和 Uref 缩放。这不是“最终物理误差百分比”，也不等于其他软件同名 residual。

下表将本项目归一化门槛直接设为 0.05/0.01；如果老师指“残差相对初值”或“监测量相对变化”，定义另有不同。连续性门未放宽。严格解仍有已知曲壁物理误差，只用作同网格迭代参照。

2. coupled 的“10 轮”里包含什么

SIMPLE 先解速度，再用近似的局部速度响应修正压力，通常还以 0.6/0.25 松弛逐步更新。这里的 coupled 联立速度两分量和压力，在一轮内用块 FGMRES 反复求解完整冻结响应，并嵌套压力预条件求解；它不使用 SIMPLE 的这两个松弛因子，而用线搜索控制更新。

至少 10 轮是共用停止函数中的下限。小圆环的 10 轮实际有 141 次块 Krylov 和 4,498 次压力迭代；细圆环为 263 / 31,058。外轮数不能直接代表总工作量或耗时。研究 DFG 的 coupled 24 轮耗时约 11.17 秒，SIMPLE 481 轮约 6.61 秒；后者加 Anderson/adaptive 为 270 轮、约 3.92 秒。它们达到接近的同离散场，但每轮工作和内部线性策略不同。

3. GPU 正确性与性能

可选原生 C++ 模块直接复用已安装 Torch 的 CUDA 运算，Jacobi/IC(0) 用双精度，返回后仍用原生矩阵检查原来的真实残差；不静默转回 CPU。IC(0) 因子在 CPU 构造，三角求解在 GPU。GPU 多重网格尚未实现，表中的 aggregation 是现有 CPU 对照。

完整 484 格圆环：CPU IC(0) 约 0.39 秒，GPU IC(0) 约 19.13 秒，均为 127 轮；速度分量差约 8.9e-16 Uref。profile 表明主要额外成本在细碎迭代运算/同步，不只是上传。262,144 未知量压力子问题，GPU Jacobi 相对 CPU Jacobi 约 5.70 倍，但 CPU 多重网格仍略快。不能据此声称大规模完整 CFD 已提速。

4. 后续采用范围

保留 CPU 默认与 GPU 实验入口。优先继续修复默认 SIMPLE 的压力离散/曲壁一致性，并减少外迭代；大规模线性求解继续研究多重网格及 GPU 上的预条件实现。当前数据不支持把现有 GPU 原型设为通用默认。
