# 阶段 0 数据结构审查

## 审查结论

阶段 0 的基础结构可以支持后续 STL/BVH 工作，但当前可视化输出路径存在明确的规模限制。
均匀网格只保存计算域、网格维数和间距，不为每个 Cartesian 单元分配对象。单元 ID、
键、包围盒和中心均按需确定性计算。

在记录的 Apple M1 编译器 ABI 下实测：

- `UniformCartesianGrid`：共 88 字节，与单元数量无关；
- `MortonCode`：8 字节；
- `CellKey`：作为单独 AoS 值时为 16 字节；
- 均匀网格核心的每单元存储：0 字节；
- 100 万单元中心分类基准进程的峰值 RSS：8,781,824 字节。

`CellKey` 被有意设计成值类型和接口类型。未来的千万叶单元八叉树不得保存一千万个
带填充的 `CellKey` 对象，而应按照项目总纲使用由 64 位 Morton 编码索引的紧凑 SoA 数组。

## 确定性

遍历顺序为 `i` 最快，其次是 `j`，最后是 `k`。线性单元 ID 可以与 `CellKey` 往返转换。
Morton 编码在 64 位值中为每个坐标轴使用 21 位，并拒绝更大的坐标。相同球体案例重复
运行得到结果哈希 `a5370e0889e02494`；独立生成的 VTU 文件具有相同的 SHA-256 摘要。

## 百万级以上输出前的已知限制

阶段 0 的 VTU 写出器以流式方式输出点和连接关系，因此不会在内存中保留显式拓扑。
当前仍使用较冗长的 ASCII XML，单元数据字段也以完整 `std::vector<double>` 数组传入。
在输出千万单元可视化文件前，应增加附加二进制或压缩 VTK 数据，以及分块单元字段回调。
这是输出可扩展性任务，并不意味着当前已经存在自适应八叉树或 Cut-cell 数据结构。

## 阶段边界决定

阶段 0 结束并不意味着可以立即开发 Cut-cell。下一步应先执行阶段 1：封闭 STL 诊断、
BVH 加速，以及带解析和外部验证的均匀网格分类。自适应八叉树仍属于阶段 2。
